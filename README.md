Создать и настроить Dockerfile, а затем создать образ приложения с учётом вашего Docker ID и c тегом v1.

## Что можно улучшить
1. Сделать второую фазу FROM. Так как для работы программы goland не нужен, то можно собранный исполняемый
файл из первого образа передать во второй "облегченный" образ, где нет goland. Нужно только разобраться
на какой OS построен образ golang:1.22.0... И тогда установку sqlite можно перенести во вторую фазу. 
Интересно насколько меньше будет итоговый образ по размеру...
2. Подумать над более тесной группировкой через &&, чтобы сократить кол-во шагов.

# Полезности для проверки реализации
## Сборка образа
```
docker build -t karabasbarabas1276/go-basic-sprint11:v1 .
```
Если нужно пересобрать заново без кэша, то
```
docker build --no-cache -t karabasbarabas1276/go-basic-sprint11:v1 .
```


## Запуск контейнера
Запустить контейнер с автоматическим удалением контейнера при выходе:
```
docker run --rm karabasbarabas1276/go-basic-sprint11:v1
```
При запуске контейнера он в консоль выведет логи работы приложения.

## Альтернативная проверка результата работы приложения в БД

1. Запуск контейнера в интерактивном режиме 
```
docker run --rm -it karabasbarabas1276/go-basic-sprint11:v1 bash
```

2. Запустить вручную программу:
```
> /opt/go-app/go-basic-sprint11
```

3. Запустить sqlite и проверить что лежит в БД
```
> sqlite3
sqlite> .open tracker.db
sqlite> .mode table
sqlite> select * from parcel;
sqlite> .quit
```
В БД должны появиться записи с актуальной датой создания.

4. Проверить под каким пользователем идет работа
```
> id
```

5. Права на работу с файлами

```
> ls -la
> cd ..
> ls -la
```

6. Выйти из контейнера
```
exit
```
Контейнер автоматически удалиться благодаря опции запуска `--rm`.
