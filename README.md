# Финальное задание
Создать и настроить workflow (github) для автоматического тестирования и публикации приложения в DockerHub.

# Решение
См. [go_ci_cd](/.github/workflows/go_ci_cd.yaml) и [Dockerfile](/Dockerfile)

## Особенности
Сборка образа происходит в две фазы:
 1. Фаза 1 подготовительная. Собирается go приложение.
 2. Фаза 2 финальная. На минимальную linux конфигурацию переносится приложение вместе с пользователями и правами. Получам следующие размеры образа:

    2.1. `FROM scratch` - 9 Мб

    2.2. `FROM alpine` - 17 Мб

    2.3. `FROM debian:stable-slim` - 87 Мб

Если сделать сборку образа, состоящей только из фазы 1, то вес будет 1.25 Гб.

# Полезности для проверки реализации
## Сборка образа
```
docker build -t karabasbarabas1276/go-basic-sprint11:v1.0.1 .
```
Если нужно пересобрать заново без кэша, то
```
docker build --no-cache -t karabasbarabas1276/go-basic-sprint11:v1.0.1 .
```

## Запуск контейнера
Запустить контейнер с автоматическим удалением контейнера при выходе:
```
docker run --rm karabasbarabas1276/go-basic-sprint11:v1.0.1
```
При запуске контейнера он в консоль выведет логи работы приложения.

## Альтернативная проверка результата работы приложения в БД

1. Запуск контейнера в интерактивном режиме 
```
docker run --rm -it karabasbarabas1276/go-basic-sprint11:v1 bash
```

2. Запустить вручную программу:
```
> /opt/go-app/go-basic-sprint11
```

3. Запустить sqlite и проверить что лежит в БД (требует установки sqlite)
```
> sqlite3
sqlite> .open tracker.db
sqlite> .mode table
sqlite> select * from parcel;
sqlite> .quit
```
В БД должны появиться записи с актуальной датой создания.

4. Проверить под каким пользователем идет работа
```
> id
```

5. Права на работу с файлами

```
> ls -la
> cd ..
> ls -la
```

6. Выйти из контейнера
```
exit
```
Контейнер автоматически удалится благодаря опции запуска `--rm`.
